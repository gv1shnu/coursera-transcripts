In this unit, we covered the fundamentals of the MongoDB database and it's flexible document model for storing data. We also learned how to use the Atlas Data Explorer to manage data from the Atlas UI. MongoDb is a general purpose document database suitable for a wide variety of use cases. MongoDb's casing like documents offer a flexible and developer friendly way to work with data.

Remember how data is organized in MongoDB. The document is the basic unit of data in MongoDB. A collection is a grouping of those documents, and a database is a container for collections. In MongoDB, documents are displayed in JSON but stored in BSON.

BSON is an extension of JSON that supports additional data types like dates, numbers of various types, and object IDs. Remember that an object ID is a datatype in MongoDB that creates a unique identifier for the required Id field. MongoDb's flexible schema gives developers a lot of freedom to modify the structure of the application data without extensive setup or downtime. MongoDb's data model supports polymorphic data so by default, documents within a collection can contain different fields and value types.

We can always constrain the structure of those documents using the option of schema validation if you need to. The MongoDB database is at the core of MongoDB Atlas. You can use the Atlas Data Explorer to manage databases, collections, and documents right from the Atlas UI. Thinking about the next steps?

Now that you've learned about MongoDB and the document model, you might want to learn how to perform CRUD operations using MongoDB. Check out our courses on CRUD or take a look at MongoDB's docs. Congratulations on completing this unit on the MongoDB database and the document model. Until next time, keep coding.
